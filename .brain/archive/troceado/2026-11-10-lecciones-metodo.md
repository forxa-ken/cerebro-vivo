# Lecciones: metodo

Formato: problema → causa → regla. Las escribe `lecciones.py` en el momento del hito (spec 026).

- **Al escribir código con un script Python en heredoc se coló un salto de línea real dentro de un texto y rompió la sintaxis** → un \n dentro de comillas triples se interpreta al ejecutar el script que escribe el archivo → **escribir código con Edit o Write, o doblar la barra (\n), y comprobar la sintaxis con ast.parse antes de seguir** (2026-11-07)
- **Al editar archivos con Python desde la terminal, los saltos de linea escritos como barra-n dentro de textos largos acabaron como saltos reales y rompieron el archivo (instalar.py y arranque.py no arrancaban)** → El texto pasa por varias capas de comillas y escapes (heredoc, cadena de Python, archivo destino) y cada una reinterpreta la barra → **Para textos largos usar la herramienta Write o Edit en vez de scripts con escapes, y tras cada edicion de .py comprobar que compila con ast.parse o python -c antes de seguir** (2026-11-08)
- **Una prueba repartida a los proyectos falló en LoboHook tras actualizar a 1.25.0** → test_todos_los_guardianes_usan_textos recorría todos los guardianes de la carpeta y LoboHook tiene uno propio (modo auto) que el arnés no reparte → **Una prueba que se reparte no debe suponer que todo lo que hay en la carpeta es del arnés: filtrar por manifiesto.json o arnes_instalado.json, y probarla con un archivo ajeno** (2026-11-08)
- **Al investigar fuentes web, la página de OpenAI devolvió 403 al lector automático (WebFetch) y al agente web-fetch** → Algunas webs rechazan a los lectores automáticos pero abren en un navegador real → **Si una fuente da 403, abrirla en el navegador integrado (navigate + get_page_text) antes de pedirle a Darwin que pegue el texto** (2026-11-08)
- **Otra vez (ya es la tercera) un salto de linea escrito como barra-n dentro de un texto generado por un script Python en heredoc acabo como salto real y rompio la sintaxis (actualizar_arnes.py y test_arnes_actualizar.py en la 1.27.1)** → Se repitio el patron de las lecciones anteriores: insertar bloques de codigo con scripts que pasan por heredoc, cadenas Python y replace; las dos primeras lecciones no se aplicaron porque eran consejos, no un paso fijo → **Para bloques de codigo de mas de 3 lineas usar siempre Edit o Write (nunca un script con heredoc); y tras cualquier insercion hecha por script, correr python -c ast.parse del archivo antes de seguir** (2026-11-08)
- **Cuarta vez (la regla acababa de escribirse en la constitucion): al anadir una linea con barra-n escrita en un script Python en heredoc, quedo un salto de linea real y partio la regla en dos lineas** → La regla se redacto para bloques de mas de 3 lineas y la aplique solo a ellos; las ediciones pequenas de texto con script tambien pasan por varias capas de escapes y fallan igual → **Ningun texto con barra-n va dentro de un script en heredoc, ni siquiera una linea: usar Edit/Write, o construir el caracter con chr(92) y chr(10); y comprobar el resultado con grep antes de dar por hecho** (2026-11-08)
- **Una prueba nueva del repo (test_esperando_prueba.py, 1.28.2) se repartio a los proyectos y fallaba alli** → usaba VERSION y CAMBIOS.md, que solo existen en el repo del arnes, y su nombre no empezaba por test_arnes_ (unico patron que el manifiesto no reparte); las pruebas del repo pasaban y no se vio hasta actualizar otro proyecto → **toda prueba que lea archivos del repo (VERSION, CAMBIOS.md, manifiesto) se llama test_arnes_*.py; tras anadir un test, mirar si aparece en manifiesto.json y correrlo en un proyecto actualizado** (2026-11-08)
- **El guardian eventos_chat (1.27.0) no bloqueaba git push con una libreria vulnerable instalada en un .venv, y el punto 28 se cerro por un 'ya lo probamos' sin detalle** → version_instalada usa importlib.metadata del Python que ejecuta el hook, que no ve el .venv del proyecto; las pruebas unitarias simulaban la instalacion en el mismo Python y nunca usaron un entorno aparte; ademas se cerro sin saber que se habia probado → **todo guardian que mire el entorno se prueba con un .venv real (libreria en el venv, hook con el Python del sistema); un 'ok' sin detalle sobre una prueba de seguridad se anota como no verificado y no se cierra el punto** (2026-11-08)
- **Un guardian de ordenes recordaba para siempre django 3.2 y avisaba de 'librerias (2)'** → el recuerdo solo se limpiaba al pasar la revision y el parser de la orden tomaba el '2' de '2>&1' por una libreria → **al leer ordenes de terminal ignorar redirecciones, y todo estado que recuerda 'lo instalado' debe poder comprobarse contra el entorno real y olvidar lo que ya no esta** (2026-11-08)
