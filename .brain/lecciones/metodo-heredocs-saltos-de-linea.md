# Lecciones: metodo-heredocs-saltos-de-linea

Formato: problema → causa → regla. Las escribe `lecciones.py` en el momento del hito (spec 026).

- **Al escribir código con un script Python en heredoc se coló un salto de línea real dentro de un texto y rompió la sintaxis** → un \n dentro de comillas triples se interpreta al ejecutar el script que escribe el archivo → **escribir código con Edit o Write, o doblar la barra (\n), y comprobar la sintaxis con ast.parse antes de seguir** (2026-11-07)
- **Al editar archivos con Python desde la terminal, los saltos de linea escritos como barra-n dentro de textos largos acabaron como saltos reales y rompieron el archivo (instalar.py y arranque.py no arrancaban)** → El texto pasa por varias capas de comillas y escapes (heredoc, cadena de Python, archivo destino) y cada una reinterpreta la barra → **Para textos largos usar la herramienta Write o Edit en vez de scripts con escapes, y tras cada edicion de .py comprobar que compila con ast.parse o python -c antes de seguir** (2026-11-08)
- **Otra vez (ya es la tercera) un salto de linea escrito como barra-n dentro de un texto generado por un script Python en heredoc acabo como salto real y rompio la sintaxis (actualizar_arnes.py y test_arnes_actualizar.py en la 1.27.1)** → Se repitio el patron de las lecciones anteriores: insertar bloques de codigo con scripts que pasan por heredoc, cadenas Python y replace; las dos primeras lecciones no se aplicaron porque eran consejos, no un paso fijo → **Para bloques de codigo de mas de 3 lineas usar siempre Edit o Write (nunca un script con heredoc); y tras cualquier insercion hecha por script, correr python -c ast.parse del archivo antes de seguir** (2026-11-08)
- **Cuarta vez (la regla acababa de escribirse en la constitucion): al anadir una linea con barra-n escrita en un script Python en heredoc, quedo un salto de linea real y partio la regla en dos lineas** → La regla se redacto para bloques de mas de 3 lineas y la aplique solo a ellos; las ediciones pequenas de texto con script tambien pasan por varias capas de escapes y fallan igual → **Ningun texto con barra-n va dentro de un script en heredoc, ni siquiera una linea: usar Edit/Write, o construir el caracter con chr(92) y chr(10); y comprobar el resultado con grep antes de dar por hecho** (2026-11-08)
- **Quinta vez: un salto de linea escrito con barra-n dentro de un script Python en heredoc dejo una cadena partida en tests/test_medir.py (SyntaxError)** → la regla de usar Edit o Write no se aplico al anadir una prueba nueva con un script, y la reparacion con replace tambien fallo porque el archivo ya tenia el salto real → ****para anadir o corregir codigo, incluidas pruebas, usar siempre Edit o Write; si ya esta roto, Edit sobre el texto roto y ast.parse o la prueba antes de seguir**** (2026-11-10)
- **Al generar archivos de prueba con un script en heredoc, los saltos de linea escritos como barra-invertida doble + n llegaron como saltos reales y rompieron los textos entre comillas (SyntaxError, tres veces)** → La herramienta de terminal interpreta las secuencias de escape antes de que Python las lea → **Para meter saltos dentro de un texto generado, usar chr(10) o la herramienta Edit/Write en vez de escapes en un heredoc, y ejecutar el archivo generado antes de seguir** (2026-11-11)
- **Volví a romper dos archivos con un script Python en heredoc (\n dentro de ''' se volvió salto real) pese a tener la lección** → escribí bloques de código con script en vez de Edit → **para código de más de 3 líneas usar Edit o Write siempre, y comprobar con ast.parse antes de seguir** (2026-11-11)
- **Al añadir una prueba con un script Python en heredoc, el salto de línea "\n" quedó como un salto real dentro del texto, rompió test_medir con SyntaxError y mi parche por script no cambió nada sin avisar** → las barras invertidas en un script pegado por shell se interpretan en capas y mi reemplazo de texto no comprobaba que hubiera cambiado el archivo → **no meter código con escapes por heredoc: usar Edit/Write o chr(10); y tras un parche por script comprobar con grep o lectura que el cambio quedó antes de seguir** (2026-11-12)
- **Un script de Python en heredoc dejó saltos de línea reales dentro de cadenas de una prueba (SyntaxError), y luego otra prueba falló por haber editado un archivo después de generar el manifiesto** → los \n del heredoc se convirtieron en saltos de línea al escribir el archivo; y el manifiesto guarda la huella de cada archivo → **para escribir código con \n usar Edit, no heredocs de Python; y tras tocar cualquier archivo del arnés lanzar generar_manifiesto.py ANTES de las pruebas, cada vez** (2026-11-13)
